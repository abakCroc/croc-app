# Plan: Replace ProcessBuilder.exec() with JNI + pipe

## Problem

Android 16 "Baklava" blocks `execve()` from the app process, even from `nativeLibraryDir`.
The current architecture builds croc as a renamed Go executable (`libcroc.so` with `CGO_ENABLED=0`)
and runs it via `ProcessBuilder` → `execve()`. This is blocked on Android 10+ and completely
broken on Android 16.

## Solution

Build croc as a **real shared library** (`-buildmode=c-shared` with `CGO_ENABLED=1`), load it
via `System.loadLibrary()` (which uses `dlopen()` — always allowed), and call its functions
through JNI. Go-side redirects `os.Stderr` to a pipe; Kotlin reads from the pipe fd using the
**same `parseOutput()` logic** as before.

```
Kotlin (CrocProcess)
  │
  ├── System.loadLibrary("croc")     ← dlopen(), always works on Android
  │
  ├── CrocNative.crocStart(config)   ← JNI → Go
  │     Go: os.Stderr → pipe.WriteEnd
  │     Go: cli.Run(args) in goroutine
  │     Go: returns pipe.ReadEnd fd
  │
  ├── FileInputStream(fd)            ← same as reading Process.inputStream
  │     ↓ parseOutput()              ← UNCHANGED
  │
  └── CrocNative.crocWait()          ← exit code
```

## Critical detail: stderr, not stdout

croc writes **all** progress output to `os.Stderr` (via `fmt.Fprintf(os.Stderr, ...)`).
The pipe must capture `os.Stderr`, not `os.Stdout`. The `--quiet` flag redirects stderr
to `/dev/null` — we must NOT use it.

## Step 1: Create `third_party/croc-src/capi.go`

Go C-API wrapper with three exported functions:

```go
package main

/*
#cgo LDFLAGS: -landroid -llog
#include <jni.h>
#include <stdlib.h>

// Helper: get string from Java string array element
static jstring getStringArrayElement(JNIEnv *env, jobjectArray arr, int i) {
    return (*env)->GetObjectArrayElement(env, arr, i);
}
*/
import "C"

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "sync"
    "unsafe"
    "github.com/schollz/croc/v10/src/cli"
    "github.com/schollz/croc/v10/src/utils"
)
```

### Exported function: `crocStart`

- Accepts: JSON config string (via JNI `jstring`)
- Config JSON: `{"args":["croc","--yes","send",...], "env":{"HOME":"...","CROC_SECRET":"..."}, "workDir":"..."}`
- Sets `os.Args` from config
- Sets environment variables via `os.Setenv()`
- Calls `os.Chdir()` for workDir
- Creates `os.Pipe()` → redirects `os.Stderr` to write end
- Starts `cli.Run()` in a goroutine with `sync.WaitGroup`
- Returns pipe read-end **file descriptor** as `int`

### Exported function: `crocWait`

- Blocks until `cli.Run()` goroutine finishes
- Restores original `os.Stderr`
- Calls `utils.RemoveMarkedFiles()`
- Returns exit code (0 = success, 1 = error)

### Exported function: `crocCancel`

- Signals cancellation (closes a channel or sets a flag)
- The running goroutine checks this and returns early

### JNI naming

Functions use explicit JNI naming convention so Kotlin `external fun` works directly:

```go
//export Java_com_dking_crocapp_croc_CrocNative_crocStart
func Java_com_dking_crocapp_croc_CrocNative_crocStart(
    env *C.JNIEnv, obj C.jobject, configJson C.jstring,
) C.jint { ... }
```

The Go code uses CGO preamble C helpers to convert JNI `jstring` → Go `string`:
```c
static const char* jstringToUTF(JNIEnv *env, jstring s) {
    return (*env)->GetStringUTFChars(env, s, NULL);
}
static void releaseUTF(JNIEnv *env, jstring s, const char* utf) {
    (*env)->ReleaseStringUTFChars(env, s, utf);
}
```

### Exit handler

Replace `os.Exit()` calls in vendored croc source (3 places in `cli.go`):
- Line 207: classic mode toggle → replace with `return nil`
- Line 448: missing CROC_SECRET → replace with `return fmt.Errorf("CROC_SECRET required")`
- Line 721: missing CROC_SECRET → replace with `return fmt.Errorf("CROC_SECRET required")`

This prevents `os.Exit()` from killing the entire app process when running as a library.

## Step 3: Create `CrocNative.kt`

New file: `app/src/main/java/com/dking/crocapp/croc/CrocNative.kt`

```kotlin
package com.dking.crocapp.croc

import android.util.Log
import org.json.JSONObject

object CrocNative {
    private const val TAG = "CrocNative"
    private var loaded = false

    init {
        System.loadLibrary("croc")
        loaded = true
        Log.i(TAG, "libcroc.so loaded via dlopen")
    }

    // Returns pipe read-end fd (>= 0) or -1 on error
    external fun crocStart(configJson: String): Int

    // Blocks until cli.Run() finishes. Returns exit code.
    external fun crocWait(): Int

    // Signals cancellation
    external fun crocCancel()

    fun buildConfigJson(
        args: List<String>,
        env: Map<String, String>,
        workDir: String
    ): String {
        val json = JSONObject()
        json.put("args", org.json.JSONArray(args))
        val envObj = JSONObject()
        env.forEach { (k, v) -> envObj.put(k, v) }
        json.put("env", envObj)
        json.put("workDir", workDir)
        return json.toString()
    }
}
```

## Step 4: Update `CrocProcess.kt`

### Changes to `runCommand()`

Replace `binaryManager.startProcess()` with JNI calls:

```kotlin
private var pipeFd: Int = -1

private suspend fun runCommand(
    command: List<String>,
    workDir: File,
    waitingState: CrocTransferState,
    extraEnv: Map<String, String>
): ProcessResult {
    val env = buildMap {
        put("HOME", homeDir.absolutePath)
        put("TMPDIR", tmpDir.absolutePath)
        putAll(extraEnv)
    }

    val configJson = CrocNative.buildConfigJson(
        args = command,        // ["croc", "--yes", "send", "file.txt", ...]
        env = env,
        workDir = workDir.absolutePath
    )

    pipeFd = CrocNative.crocStart(configJson)
    if (pipeFd < 0) {
        throw IllegalStateException("crocStart returned fd=$pipeFd")
    }

    _state.value = waitingState

    // Read from pipe — same as reading Process.inputStream
    val pfd = ParcelFileDescriptor.adoptFd(pipeFd)
    val inputStream = FileInputStream(pfd.fileDescriptor)
    return parseOutput(inputStream)  // ← slightly modified to accept InputStream
}
```

### Changes to `cancel()`

```kotlin
fun cancel() {
    CrocNative.crocCancel()
    closePipeFd()
    _state.value = CrocTransferState.Cancelled
}
```

### Changes to `parseOutput()`

- Change signature from `parseOutput(process: Process)` to `parseOutput(inputStream: InputStream)`
- Remove `waitForExitCode()` — replaced by `CrocNative.crocWait()` called after parseOutput
- Rest of parsing logic stays identical (regex patterns, progress state updates, etc.)

### Changes to `executeWithDnsFallback()`

After `parseOutput()` returns, call `CrocNative.crocWait()` to get exit code:

```kotlin
var result = runCommand(baseCommand, workDir, waitingState, extraEnv)
result = result.copy(exitCode = CrocNative.crocWait())
closePipeFd()
```

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| `os.Exit()` in deep croc code kills app | Patch all 3 occurrences in cli.go; search other files for `os.Exit` |
| `readline` needs terminal (no stdin on Android) | Always pass `--yes` + `CROC_SECRET` env → readline path is never hit |
| `CGO_ENABLED=1` requires NDK on build machine | CI has NDK; document local setup in README |
| `-buildmode=c-shared` increases .so size | `-ldflags=-s -w` strips debug; croc is ~8MB per ABI |
| `croc` creates `configDir` at `~/.config/croc/` | Set `HOME` env to app-internal dir via config JSON |
| Pipe fd leak on cancellation | `closePipeFd()` in `cancel()` and in `finally` block |
| `os.Stderr` redirect affects other goroutines | Go's single-process model means croc owns stderr during transfer; restore after `crocWait()` |
| Progress bar writes ANSI escape codes to stderr | `parseOutput()` already handles `\r` and ANSI in regex patterns |
